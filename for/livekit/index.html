Five design calls I actually made

These are decisions from AndrewOS, translated into Python sketches so they sit next to your framework instead of behind my private repo. The syntax is illustrative. The tradeoffs are the real thing. I'm not claiming this is shipped Python, and I'd rather be caught being precise about that than get a nod for something I didn't do.

orchestrate.py 
# Two ways to run work, and the choice itself is the API.
# The caller has to say which one it wants, at the call site.

@orchestrator.route("inbound")
async def dispatch(task: Task, ctx: Context) -> Result:
    plan = ctx.decompose(task)

    if plan.is_sequential:
        # Same context. The next step reads the prior result,
        # so fidelity beats wall clock and we stay in-process.
        return await ctx.call(plan.steps)

    # Independent work. Fan out, keep the parent free,
    # accept that each child starts cold.
    return await ctx.gather(
        ctx.spawn(step, isolation="fresh") for step in plan.steps
    )
why it looks like that

The interesting decision here is not the scheduler. It is that I refused to let the framework infer sequential against parallel on the caller's behalf. Inference is right on the cheap cases and wrong on the expensive ones, and the expensive ones are exactly where a developer needs to know what happened.

So the call site declares intent and the framework honors it. That costs the developer one extra thought and it buys back every debugging session where somebody has to reconstruct why their steps ran out of order.

class Reviewer(Agent):
    """A reviewer never shares a context with what it reviews."""

    isolation = Isolation.FRESH   # deliberately not configurable

    async def run(self, artifact: Artifact) -> Findings:
        if artifact.produced_by is self.identity:
            raise SelfReviewError(artifact.produced_by)
        return await self.inspect(artifact)
why it looks like that

This one started as a config flag and I took the flag away, because the flag kept getting flipped. An agent that reviews its own output agrees with itself close to every time, and it agrees in a confident voice, which is worse than disagreeing.

My rule for framework design came out of this. If an invariant is load bearing and a tired person can turn it off at 11pm, it does not belong in configuration. Put it in the type and let the exception be loud.

# Code computes and verifies. The model extracts and judges.
# Anything checkable deterministically is not a prompt.

GATES = (
    lint_gate,      # non-zero exit blocks the send outright
    dedupe_gate,    # queries the live source, never a local log
    freeze_gate,    # one flag file halts every outbound loop
)

async def emit(draft: Draft) -> Sent | Blocked:
    for gate in GATES:
        verdict = gate(draft)
        if not verdict.ok:
            return Blocked(gate=gate.name, reason=verdict.reason)
    return await transport.send(draft)
why it looks like that

Every gate returns a reason rather than a boolean. A framework that tells a developer no without telling them why is a framework people learn to route around, and the routing around is invisible until it is a support ticket.

The dedupe gate line matters more than it reads. I originally checked a local run log, which was fast and which lied whenever a run half finished. It now queries the live source of truth and it fails closed. Fast and wrong is the worst quadrant to design a default into.

@dataclass(frozen=True)
class TraceEvent:
    stage: str
    received: Ref           # what came in
    decided: str            # what this stage chose
    because: str            # why, in one line
    handed_to: str | None   # where it went next, if anywhere

# Append-only, one file per run. A finished run reads top to
# bottom as a replay of every decision, including the refusals.
why it looks like that

This is the piece I would push hardest on if I joined. Agent systems fail quietly, and they fail in the space between two stages, which is precisely the space no single stage logs. If the trace is bolted on afterward, the first real production incident becomes archaeology instead of a read.

The because field is the one people cut and the one I would defend. A trace that records what happened without recording why is a transcript, and a transcript does not tell you which prompt or which threshold to change.

class Gate(Enum):
    AUTO    = auto()   # reversible and cheap, runs unattended
    NOTIFY  = auto()   # runs, then tells the human afterward
    CONFIRM = auto()   # stops and waits for a human answer

def gate_for(action: Action) -> Gate:
    if action.is_irreversible or action.spends_money:
        return Gate.CONFIRM
    if action.is_externally_visible:
        return Gate.NOTIFY
    return Gate.AUTO
why it looks like that

The gate is a property of the action, not a setting on the agent. That keeps the safe default in exactly one function instead of scattered across every caller who was in a hurry.

It also means adding a new action type forces you through this function, so the question of whether a human should see it gets asked at authoring time rather than after the first thing gets sent that should not have been sent.
