Your posting asks for someone who finds friction firsthand. Here's my actual log.

These are real problems in a system I run every day, and what I did about each one. Open a row to see the fix rather than the claim.

Cloning the repo gave me code, docs, and memory. It didn't give me symlinks, helper binaries, installed CLIs, tool server configs, or scheduled jobs. So a second machine looked fine and quietly behaved differently.

I wrote the environment down as a real bootstrap procedure instead of tribal knowledge, and I made it explicit which pieces are machine-local rather than version controlled. The failure I care about most is the silent one, so the bootstrap also names the things you must not load on a second machine, because two machines running the same schedule means everything fires twice.

This is the classic one. Autonomous loops on a schedule are fine right up until a job overlaps itself or a retry replays an action that should only ever happen once. In my case the blast radius was outbound messages, which is the worst kind of thing to send twice.

I put a duplicate guard in front of the send path that fails closed, keyed on the recipient rather than on the message, and checked against the live source of truth rather than a log file the system wrote itself. A log the system wrote is not evidence about the system.

Nothing was broken. Things were just quietly stale, and I only found out when I happened to open the right file. That's the same problem as a build that gets slower by two percent a week.

I built automated daily, weekly, and monthly sweeps that run without anyone invoking them, plus a live dashboard covering job health, queues, source freshness, and unresolved signals. The sweeps write a short read-once summary so an agent starting cold is grounded in current state instead of guessing. You can't prioritize friction you aren't measuring, which is the part of your posting I nodded at hardest.

Model output that reads well is the most expensive kind of defect, because review fatigue is real and a confident paragraph slides through.

So I stopped asking a model to judge it. I wrote a deterministic linter that machine checks generated text against written rules and exits nonzero when it finds a violation, and I wired it into the gates ahead of anything leaving the system. That moved correctness from model judgment into code, which is the same reason I'd want guardrails under any GenAI developer tooling before a team is asked to depend on it.
