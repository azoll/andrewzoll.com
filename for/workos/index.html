"Build internal tools that become part of people's daily work: agents, automations, and workflows that are stable, observable, and easy to maintain."

Keeping an agent loop running without a person watching it took about twenty small Python control scripts with ten test files. There's a round cap keyed to the ticket, a watchdog that acts on silence, quota cleanup so finished workspaces stop holding slots, and the event poller. Each one exists because something went wrong once.

In AndrewOS every agent writes a structured trace: what it received, what it decided, why, and what it handed off. A finished run reads top to bottom as a replayable record. Observability wasn't a nice-to-have. It was the thing that made autonomy survivable.

"You think about failure modes, observability, and ownership, not just whether the demo works."

Every change on the Coder platform had to clear a reviewer from a different model family than the one that built it, and mutation tests checked that the tests could actually fail. Across about 1,200 review verdicts on about 350 pull requests, that gate recorded more than 430 confirmed defect catches and 21 false flags.

My favorite catch: the token-rotation transaction in that MCP authorization server passed every test against an in-memory fake. A cross-family reviewer flagged it at review round 5, because production Redis runs in cluster mode and the transaction would have failed on every token refresh. The fix put the keys in one hash slot and added a test that checks the slot of each key. The round cap has a story too. I added it after one spec spent 14 review rounds over 12 hours without converging.
