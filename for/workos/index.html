"You think about failure modes, observability, and ownership, not just whether the demo works."

My honest answer here is that I learned this the expensive way. An early version of my outreach automation could send the same message twice to the same person, which is the kind of bug that costs you a relationship rather than a request. The fix wasn't a better prompt. It was a deterministic dedupe layer that reads the live sent-mail record, fails closed when it can't read it, and refuses the send.

That pattern is now everywhere in the system: hard gates written in plain code around the parts where a model being creative would be a disaster. A deterministic linter blocks anything going out under my name. A freeze flag halts all sending when the bounce rate crosses a threshold. Models decide what to say. Code decides whether it's allowed to leave.
